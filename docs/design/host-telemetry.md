# Host telemetry sampler

`shared/host-telemetry.ts` defines capability version 1, validated host information, samples, disk space, minute aggregates, process inventory, and live messages. Missing metrics and rates without a previous reading are `null`, not zero. Before the first sample, snapshot information and the latest sample are also `null`. Process start times are Linux start ticks; process CPU can exceed 100% across cores. The separate on-demand scanner and conservative attribution rules are described in [Host monitor](host-monitor.md).

`HostTelemetrySampler` in `server/host-telemetry/` is inert until `start()`. `setViewers(n)` switches between a 1-second interval with viewers and 15 seconds otherwise. `snapshot()` returns copied information, the latest reading, up to 61 samples from the last 60 seconds, and disk space for the data directory's mount. `history()` returns up to 1,440 UTC-aligned minute buckets, including the current partial minute, with per-metric min/avg/max calculated only from available readings. A backward wall-clock adjustment drops buckets newer than the current minute so they cannot evict current readings. History is memory-only and disappears on restart; missing minutes are not fabricated.

The thin Linux reader uses `fs/promises`, native OS metadata, and `statfs` (space available to this user). It caches static metadata and reads only the five metric files and disk space each interval. Partial `/proc` availability yields partial samples and diagnostics in `status()`. WSL detection considers both kernel strings and `WSL_DISTRO_NAME`; consumers must label these metrics **“WSL VM, not the Windows host.”**

CPU utilization excludes duplicate guest counters and treats idle/I/O wait as non-busy. Network totals exclude `lo`. Disk totals include whole `sd*`, `vd*`, `xvd*`, `nvme<n>n<n>`, and `mmcblk<n>` devices, using 512-byte sectors. Partitions, loop/ram/zram devices, device-mapper, software RAID, and NVMe controller-path aliases are excluded to avoid counting stacked I/O twice. Devices added since the previous read establish a baseline; removed devices contribute nothing. Counter resets contribute no negative traffic, while near-boundary 32/64-bit rollover is handled per device. Rates use monotonic elapsed time between each counter file's capture, not sample completion or the wall clock. Injected readers may supply per-file `capturedAt` timestamps in the sampler's monotonic clock domain; without them, rates use the attempt start time.

The default per-sample timeout is 2 seconds. It aborts the reader, increments diagnostics, and discards late results. A reader that ignores abort retains the sampling slot until it settles: timeouts must never permit overlapping I/O. The Linux reader waits for every launched metadata, metric, and disk-space branch to settle even when one rejects on abort. `stop()` clears timers, aborts an in-flight read, and prevents late publication. Inject a reader and clock to test without accessing a real host.

## Integration boundary

In `server/app.ts`, `buildApp` constructs the service **only when the effective `hostMonitor` flag is on**, starts it from `onReady` under startup phase **`hostTelemetry.start`**, and stops it from `onClose`, on hubs and nodes alike. The sampler receives the already-resolved `dataDirectory`. The environment flag is `AGENTIC_REMOTE_FEATURE_HOST_MONITOR=on|off`, default off; the shared flags layer owns parsing and setup preservation. No client preview may activate the sampler. Construction and sampling are both absent while the flag is off.

`subscribe(listener)` observes accepted snapshots without starting sampling or changing cadence itself. The transport service owns viewer counting, caps and shutdown, and calls `setViewers` on subscription changes. See [Host monitor](host-monitor.md) for routes, authentication, timeouts, compatibility and queue limits. UI and Oracle tools remain planned.
